# Language: detail

Part of the `work-flow` contract. The rules in `SKILL.md` have priority.

Applies to: each message to the user, the state file, reports, the PR body,
and memory entries.

Rules:

- One instruction in each sentence. Use the imperative: "Run the tests."
- Maximum 20 words in an instruction. Maximum 25 words in a description.
- Maximum 6 sentences in a paragraph. One topic in each paragraph.
- Use the active voice. Say who or what does the action.
- Use simple tenses: present, past, future.
- Put the condition before the instruction: "If the test fails, stop."
- Put a warning before the step that it applies to.
- Use one word for one meaning. Use the same term for the same thing.
- Use the articles "the" and "a".
- Do not use idioms, metaphors, slang, or humour.
- Do not put more than 3 nouns together.
- Use a vertical list for 3 items or more.
- Write numbers as digits, with units.

Not applied (the other 20 percent):

- The STE word dictionary. Software terms are permitted.
- Code, commands, file names, identifiers, error messages, and quoted text. Keep these exact.
- Commit messages. Use the convention of the repository.
- Explanations in `work-explain`. A longer sentence is permitted if it makes
  a concept easier to understand.

If the user writes in a different language, answer in that language with the same rules.
